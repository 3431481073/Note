> **用户能看见、能感知的 UI 与交互，由我定死。**

> **新旧数据冲突，统一做一次迁移，把旧数据变成新数据，再导入新体系使用。**
> **不要拿后台实现细节反复来问我。**

## 二、按什么顺序读

```
  ┌─ 起点 A：v1 现状（已有的 Tauri 便签）
  │     UI_SPEC.md  ← 从 v1 导出的界面规格（740×648、双栏）
  │
  ┌─ 起点 B：v12 目标
  │     ../specs/123.txt  ← v12 规格（新增：结构树 / 标签项目 / 节点导入卡片）
  │
  ▼
  PORTING_REPORT.md        ← 两边比：能不能合、冲突在哪（2026-09-17）
  │
  ▼
  ../specs/456.txt         ← 用户口径回复：谁能拍板、数据怎么办
  │
  ▼
  IMPLEMENTATION_PLAN.md   ← 落地执行方案（分阶段 + 选型理由 + 待拍板疑问）
  │
  ▼
  DEVELOPMENT_LOG.md       ← 真的做了：踩坑、验证、认知（§8–§19 按日追加）
  │
  ▼
  🔴 【这里断了】2026-09-18 → 2026-10-01 之间没有记录（见第四节）
```

**一句话**：**先读 `UI_SPEC.md` 和 `123.txt` 知道"从哪来、到哪去"，再读 `PORTING_REPORT.md` 知道"能不能到"，最后读 `DEVELOPMENT_LOG.md` 知道"实际怎么到的"。**
